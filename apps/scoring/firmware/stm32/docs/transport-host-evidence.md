# STM32 transport host evidence

**Task:** M3-05 STM32 binary transport implementation

## Scope

The SDK-free C17 transport library under `core/stm32_transport.c` implements the
M2-05/M0-06 binary envelope for the STM32 role. It transports already
authoritative opaque bytes only; it does not create, parse, classify, or alter
a scoring decision.

Each frame has the canonical 14-byte header: ASCII `SC`, version `1`, message
type, zero 16-bit flags, big-endian 32-bit sequence, and big-endian 32-bit
payload length. Payloads are bounded to 4,096 bytes, followed by a 4-byte
reflected Castagnoli CRC-32C. The receiver validates magic, version, known type,
direction, flags, declared length, complete length, and CRC before yielding a
borrowed payload. STM32 accepts only inbound `request` frames and emits only
`decision-record`, `status`, or `response` frames.

## Failure and recovery behavior

Receive fragments are copied only into one caller-owned 4,114-byte buffer. A
fixed header is validated as soon as all 14 bytes arrive. A corrupt, duplicate,
reordered, over-capacity, or otherwise invalid frame clears the partial buffer,
delivers no payload, and blocks later receipt until the owning link lifecycle
calls the explicit recovery API with new stream sequence boundaries.

Transmission permits one prepared frame at a time. An adapter write failure is
returned unchanged and latches outbound backpressure, so no later frame is
prepared until explicit recovery. The adapter does not queue, retry, sort, or
repair frames. Both receive and transmit stop rather than wrapping after a
sequence of `UINT32_MAX`; starting a new stream is explicit.

The host integration permits diagnostic `status` and `response` messages while
unavailable, but rejects `decision-record` transmission until the STM32 host is
ready. This preserves the reset/default safe state without making transport a
scoring authority.

## Golden fixtures and host verification

`fixtures/transport-frame-golden.json` is a strict, duplicate-free source list.
`tools/generate-transport-fixture.mjs` imports the built TypeScript M2-05 codec
and emits `generated/stm32_transport_golden_frames.h`; the C tests compare C17
encoding and decoding against those generated bytes. The generator rejects
unknown root or fixture fields and duplicate fixture names.

Run the exact host verification command from the repository root:

```text
node apps/scoring/firmware/stm32/tools/test-host.mjs
```

It builds with `CMAKE_BUILD_TYPE=Release` and runs the always-active C tests.
They cover generated golden frames, fragmented receive, CRC and header
corruption, wrong direction, duplicate and reordered sequences, sequence
exhaustion, one outstanding frame, adapter backpressure, reset/default decision
suppression, and maximum payload boundaries.

## Explicit deferrals

This evidence does not provide a target HAL adapter, SPI/electrical link timing,
DMA or interrupt behavior, payload decision parsing or serialization, target
board measurements, or certification evidence. Those remain separate target,
payload-contract, and board-validation work.
